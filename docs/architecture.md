# Архитектура

## Границы плагина

`thread-activity` регистрирует одну `navPanel` с ID и путём `activity`. Он не заменяет боковую панель, не меняет настройки `thread-list` и не импортирует приватные модули приложения.

`header-activity.ts` добавляет ссылку-кнопку перед `[data-sidebar-search-button]` в заголовке BB 0.47. App overlay предоставляет React-контекст SDK: обычное нажатие вызывает `useBbNavigate().toPluginPanel("activity")` без перезагрузки приложения, а ссылка сохраняет публичный адрес `/plugins/thread-activity/activity` для открытия в новой вкладке. Кнопка появляется при наличии заголовка и кнопки плагина Sidebar Search. `MutationObserver` восстанавливает её при перерисовке заголовка и поздней загрузке поиска. Проверка соседнего элемента предотвращает повторные вставки и циклы наблюдателя. Размонтирование overlay при отключении или перезагрузке плагина удаляет добавленные ссылки, обработчики и наблюдатель.

`server.ts` — обязательная точка входа без обработчиков: собственных данных и серверной логики нет.

## Источник данных

`experimental_useSidebarThreads()` предоставляет текущий снимок тредов и проектов и использует общий кеш и realtime-подписки BB. Явного ограничения текущим проектом нет. Запрашивается стандартный жизненный цикл `active`, то есть неархивные треды. Скрытые и архивные записи дополнительно исключаются в модели представления.

`latestAttentionAt` — единственное поле времени для группировки и сортировки. Статусы, `updatedAt`, закрепление, машины, проекты, секции и родительские связи не участвуют в порядке. При равных временах используется ID. Объекты SDK не изменяются.

Семантика `latestAttentionAt` принадлежит BB: это не гарантированное время каждого сообщения или каждого события потока. Плагин намеренно не создаёт вторую систему отслеживания сообщений.

## Отображение

`activity.ts` содержит чистую модель группировки. Календарные даты вычисляются по локальному часовому поясу клиента. Для «Вчера» и следующей полуночи используется календарная арифметика, корректная для дней длиной 23 и 25 часов.

`app.tsx` превращает группы в плоскую последовательность заголовков и строк. `@tanstack/react-virtual` отображает видимую часть этой последовательности и небольшой запас. Строки имеют фиксированную высоту; длинные названия сокращаются, полный текст доступен в подсказке.

Ссылки используют `href`, предоставленный SDK. BB обрабатывает обычный переход, браузер — открытие в новой вкладке. `experimental_ThreadStatusGlyph` рисует штатный индикатор состояния.

Таймер обновляет подписи дней в следующую локальную полночь. `focus` и `visibilitychange` учитывают выход ноутбука из сна. При размонтировании таймер и обработчики удаляются.

## Проверки

```sh
npm run typecheck
npm test
npm run build
```

Тесты проверяют общий порядок, отсутствие приоритета у закреплённых и работающих тредов, дочерние чаты, исключение скрытых/архивных записей, перенос между днями, равные времена, локальный часовой пояс, границу года, переходы летнего времени, состояния загрузки/ошибки/пустого списка, ссылки, виртуализацию и очистку таймера.

Тесты интерфейса используют официальный harness `@get-bb/plugin-sdk/testing/app` и jsdom. Отдельный сканер проверяет отсутствие приватных импортов BB. Тестовый часовой пояс Europe/Berlin выбран для воспроизводимых проверок переходов летнего времени; рабочая лента использует часовой пояс клиента.

После установки нужно также проверить в BB: доступность пункта «Активность», прокрутку длинной ленты, переход в чат, светлую/тёмную тему и узкое окно. Harness не воспроизводит маршрутизацию, CSS и всю оболочку приложения.

## Обновление SDK

Сначала обновите BB, затем выполните `bb plugin types` в каталоге проекта, установите обновлённые зависимости и повторите проверки. Меняйте `engines.bbPluginSdk` только после проверки совместимости. Ручные изменения встроенного `thread-list` не нужны.
